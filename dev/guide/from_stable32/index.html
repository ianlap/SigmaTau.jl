Coming from Stable32

Stable32 and this package compute the same statistics from the same definitions, those of SP1065, whose author wrote Stable32. With Stable32's noise types and bias convention stated, the deviations agree to the five digits that Stable32 prints (Validation). A default call can differ, because this package identifies the noise and corrects bias differently in places. This page maps the functions of Stable32, as its manual describes them, onto this package, lists each difference, and shows how to reproduce a Stable32 table.

Reading a file

read_data reads the .phd and .frd files of Stable32 and text files with its header:

using SigmaTau
p = read_data("clock.phd")      # phase, with τ₀ from the Tau: line
f = read_data("clock.frd")      # fractional frequency

Without a Tau: line the sample interval comes from the time tags. MJD time tags give the record its date (start_time), and scaling= does the work of the Multiplier. The Addend:, Multiplier:, Tag Scale: and Tag Offset: lines of a header are not applied.

Zeros are gaps in a Stable32 file

Stable32 marks a missing sample with a zero: every zero of a frequency record, and every zero of a phase record but its first and last sample (Stable32 manual, "Gaps & Outliers"). read_data reads a .phd or .frd file the same way, and gives each such zero as NaN, which marks a missing sample in this package. Where the zeros are readings, as quantized data can have them, keep them:

f = read_data("counts.frd"; keep_zeros = true)

A Stable32 file under another extension is read as plain columns, in which a zero is a sample. format = :stable32 reads it as above.

The drift models are fewer here. drift_fit fits the linear, log and diffusion models of the Drift function to the frequency, and a quadratic one. detrend(p; method = :quadratic) is its quadratic fit to phase data. Where the results differ

Noise type

The noise type at each averaging time sets the EDF, and with it the interval, and for the total deviations the bias factor. Both programs use the lag-1 autocorrelation while at least 30 points remain and the $B_1$ ratio below that. They differ in these steps, for the reasons that Noise identification gives:

StepStable32SigmaTau
Before the lag-1 testnot described in its manuala least-squares quadratic is removed from each decimated series

Limits between the FM types at $τ ≥ 2τ_0$the estimate is rounded to the nearest $α$halfway between the values the estimate takes on decimated phase

Hadamard familyon the reference record, the noise type of the other overlapping estimatorsits own, found with up to three differences on the record less its frequency drift, and without the $B_1$ ratio: below 30 averaged points an FM type is the one found at the longest $τ$ that has 30

identify_noise(x, m; remove_drift = false, b1_length = :record) undoes the first, fourth and fifth steps, and its labels go to any estimator as noise. remove_drift = false on a Hadamard estimator undoes the last. No option undoes the second and third.

The labels differ in two places. One is the longest averaging times, where few averaged points remain. The other is flicker PM beyond about $16τ_0$: on the flicker PM record from Stable32's own noise generator that is among the test fixtures, Stable32 labels 32 s, 64 s and 128 s white PM and 256 s white FM, where this package reads flicker PM. Its interval for the Allan deviation at 32 s is half as wide as the one here.

correct_bias = :stable32 on an estimator, on deviation or on stability applies Stable32's convention to the total deviations and to Thêo1. The command line takes --bias stable32, and the explorer As Stable32 under Bias correction.

For theo1 the setting gives the ThêoBR of a Stable32 run with automatic noise identification. It agrees with Stable32 to the five digits that Stable32 prints on the two records compared (Validation). The default averages the same ratio over the same range, up to half the record, from every sample, where Stable32 takes 3000 at most. On the record of 1001 samples the two agree within 0.1 %, and on the record of 8192 the default reads 1.8 % lower. correct_bias = :published averages the ratio up to a tenth of the record only and can differ by far more (Bias correction). correct_bias = false gives Stable32's Thêo1 with white FM set. The factor that Stable32 applies for another noise type set by hand has no counterpart here.

theoh takes the default ratio. For the long averaging times of a Stable32 ThêoH run on more than 3000 samples, call theo1 with correct_bias = :stable32.

Gaps

Stable32 skips gaps in the Allan, Hadamard, modified total, time total and Hadamard total deviations, Thêo1, ThêoH and TIE rms, and fills them itself for the modified Allan, time and total deviations and MTIE. This package never fills on its own. The Allan and Hadamard families, MTIE and TIE rms skip gaps, and the other estimators stop with an error until the record is filled (Gaps, outliers and drift). Its fillgaps reflects the neighboring samples into a gap, where the Fill function interpolates linearly, so filled records differ.

Smaller points

  • The longest averaging time of a default grid is each estimator's own limit and can differ from Stable32's by a step: on a record of 8192 points Stable32's total deviation ends at 4096 s and totdev(p) at 2048 s. Give the factors to get a row.
  • TIE rms, MTIE and Thêo1 take a frequency record here, and integrate it. Stable32 computes them for phase data only.
  • The intervals are two-sided. Stable32 also offers single-sided limits.

Reproducing a Stable32 table

State Stable32's noise type at each averaging time, from the Alpha column of its table, and its bias convention. The reference record of the Validation page comes with Stable32's tables. A default call for its total deviation at 1024 s:

using SigmaTau
file = joinpath(pkgdir(SigmaTau), "test", "fixtures", "validation",
                "stable32gen.DAT")
p = read_phase(file)
totdev(p, [1024])
StabilityResult(:totdev, 1 pts, τ∈[1024, 1024] s, with CI)
   tau      dev  neff     ci_lo     ci_hi    edf  noise
  1024  0.00296  8190  0.002457  0.003993  9.139  FLFM

Stable32 prints 2.8694e-03 for this row, with the limits 2.4276e-03 and 3.6939e-03 and $α = 0$, white FM:

totdev(p, [1024]; noise = :WHFM, correct_bias = :stable32)
StabilityResult(:totdev, 1 pts, τ∈[1024, 1024] s, with CI)
   tau       dev  neff     ci_lo     ci_hi  edf  noise
  1024  0.002869  8190  0.002427  0.003695   12  WHFM

The deviation is Stable32's to the digits it prints, and the limits are within 0.03 % of its own. noise also takes one type for each averaging factor, so a whole table is one call. For the Allan and Hadamard families the noise type is all there is to state.
