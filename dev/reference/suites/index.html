Suites, grids and streaming

Several estimators at once

stability runs several estimators on one record with one set of keywords and returns a StabilitySuite, which is indexed by the name of the estimator.

SigmaTau.stability — Function
stability(data; devs=DEFAULT_DEVIATIONS, m=Octave, ci=true,
          confidence=DEFAULT_CONFIDENCE, correct_bias=true, remove_drift=true,
          noise=:auto) → StabilitySuite

Several deviations of one record in a single call. Each name in devs is run through deviation, and the results come back as a StabilitySuite, indexed by name.

Arguments

  • data: a PhaseData or FrequencyData record.

Keywords

  • devs: the estimators to run, as symbols or strings from estimators; one name runs one estimator.
  • m: a TauMode grid, cut for each estimator at the largest averaging factor it supports, or an integer vector that every estimator takes as it stands. theo1 reads such a vector as even Thêo1 factors (an odd entry gives NaN) and theoh as factors of $τ = mτ_0$, so prefer a TauMode when the suite mixes them with other estimators.
  • ci, confidence, noise: as in adev, for every estimator.
  • correct_bias: reaches the total estimators and theo1.
  • remove_drift: reaches the Hadamard family.

Examples

julia> using SigmaTau

julia> pd = PhaseData(collect(1.0:64.0), 1.0);

julia> suite = stability(pd; devs=(:adev, :hdev), m=Octave, ci=false);

julia> keys(suite)
2-element Vector{Symbol}:
 :adev
 :hdev

julia> suite[:adev].deviation_type
:adev
source
SigmaTau.DEFAULT_DEVIATIONS — Constant
DEFAULT_DEVIATIONS

The estimators stability runs when devs is not given: :adev, :mdev, :hdev and :mhdev. All four are fractional-frequency deviations, so the default suite shares one ordinate. The time deviations, in seconds, are run on request.

Estimators by name

deviation runs the estimator of a given name, for a choice that is made at run time. estimators lists the names with the label, the family and the unit of each. The command-line program and the explorer offer the same list.

SigmaTau.estimators — Function
estimators() → Vector{NamedTuple}

The estimators that deviation and stability run, one entry each, with the fields

  • name::Symbol: the function name, such as :adev.
  • label::String: the display name, such as "ADEV".
  • family::Symbol: :allan, :total, :theo or :time.
  • axis::Symbol: :sigma_y (fractional frequency) or :sigma_x (seconds).
  • correct_bias::Bool: whether the correct_bias keyword applies.
  • description::String: one line for menus and help.

The dynamic deviations dadev and dhdev return maps over time and τ, not σ(τ) curves, and are not listed.

Examples

julia> using SigmaTau

julia> e = estimators();

julia> e[1].name, e[1].label, e[1].family, e[1].axis
(:adev, "ADEV", :allan, :sigma_y)

julia> [x.name for x in e if x.axis === :sigma_x]
5-element Vector{Symbol}:
 :tdev
 :htdev
 :ttotdev
 :mtie
 :tierms
source
SigmaTau.deviation — Function
deviation(name, data, m=Octave; ci=true, confidence=DEFAULT_CONFIDENCE,
          correct_bias=true, remove_drift=true, noise=:auto,
          dead_time=0) → StabilityResult

Run the estimator called name, any name from estimators as a symbol or a string, on a PhaseData or FrequencyData record. deviation(:adev, data, m) is adev(data, m); use it when the estimator is chosen at run time, from a menu or a command-line option.

m is a TauMode grid or an integer vector of averaging factors. The keywords are those of adev. correct_bias reaches only the estimators that take it (the total estimators and theo1) and remove_drift only the Hadamard family, and a dead_time other than zero is an error for any estimator but :adev. mtie and tierms accept ci and confidence and report no interval. The non-overlapped forms are reached through adev and hdev directly.

The function is written as plain branches, so it compiles under juliac --trim.

Examples

julia> using SigmaTau

julia> pd = PhaseData(collect(1.0:64.0) .^ 2, 1.0);

julia> deviation(:hdev, pd, 1:3; ci=false).dev == hdev(pd, 1:3; ci=false).dev
true

τ grids

An estimator takes its averaging factors as a vector, as a range or as a grid. The six grids are the instances of TauMode: AllTaus, Octave, HalfOctave, QuarterOctave, Decade and HalfDecade. Averaging times says which to choose.

SigmaTau.TauMode — Type
TauMode

Spacing of the averaging-factor grid. Pass an instance in place of m_values, as in adev(data, Decade), or to stability and tau_values.

InstanceRatio of successive factorsGrid
AllTausevery integer1, 2, 3, 4, 5, …
Octave21, 2, 4, 8, 16, …
HalfOctave√21, 2, 3, 4, 6, 8, 11, 16, …
QuarterOctave2^(1/4)1, 2, 3, 4, 5, 6, 7, 8, 10, …
Decade101, 10, 100, 1000, …
HalfDecade√101, 3, 10, 32, 100, …

Octave is the default of every estimator. The geometric grids are rounded to integers, duplicates are dropped, and each grid stops at the largest factor the estimator supports for the record length.

source
SigmaTau.tau_mode — Function
tau_mode(s) → TauMode

The TauMode named by s, a string or a symbol, as typed on a command line or chosen in a menu. Case and separators are ignored: "half-octave", "half_octave", "halfoctave" and "HalfOctave" all give HalfOctave, and "all" or "alltaus" gives AllTaus. Any other name throws an ArgumentError.

Examples

julia> using SigmaTau

julia> tau_mode("half-decade")
HalfDecade::TauMode = 5
source
SigmaTau.tau_values — Function
tau_values(mode::TauMode, N::Int, kernel::Symbol) → Vector{Int}

Averaging factors $m$ of the grid mode for a record of N phase samples, up to the largest that the estimator kernel (:adev, :mdev, …) supports. Despite the name, the values are averaging factors, not times: $τ = mτ_0$. An estimator called with a TauMode uses this grid, so adev(data, Decade) is adev(data, tau_values(Decade, N, :adev)).

For :theo1, which takes even factors only, odd entries are rounded up to the next even value. A :theoh grid is in units of $τ = mτ_0$, and theoh chooses the Thêo1 factor for each point.

Examples

julia> using SigmaTau

julia> print(tau_values(Decade, 1000, :adev))
[1, 10, 100]

julia> print(tau_values(Octave, 20, :theo1))
[2, 4, 8, 16]

Streaming

StreamingStability keeps running sums for ADEV, MDEV, HDEV or MHDEV and updates them with each phase sample. The deviation is available while the measurement runs, and the record need not be kept.

acc = StreamingStability(:adev, 1.0, [1, 10, 100])
push!(acc, x_next)        # one phase sample
append!(acc, xs)          # several, in order
snapshot(acc)             # the StabilityResult of the samples so far
nsamples(acc)             # their number
SigmaTau.StreamingStability — Type
StreamingStability(dev, tau0, m_values)

Accumulator that updates ADEV, MDEV, HDEV or MHDEV as phase samples arrive, without keeping the record. Feed it with push! or append! and read the estimate at any moment with snapshot.

After any number of samples the deviation equals that of adev, mdev, hdev or mhdev on the samples so far.

The running sums are those of Dobrogowski and Kasznia (2007), Eqs. (6) to (14), who give them for ADEV and TDEV. The same scheme is applied here to the third differences of HDEV and MHDEV. A sample costs a fixed number of operations per averaging factor, and the accumulator holds the last $k\max(m) + 1$ samples, with $k = 2$ for ADEV, 3 for MDEV and HDEV and 4 for MHDEV. The total and Thêo estimators read the whole record at every averaging time and cannot be accumulated this way.

Arguments

  • dev: :adev, :mdev, :hdev or :mhdev.
  • tau0: sample interval in seconds.
  • m_values: averaging factors $m$, with $τ = mτ_0$.

Every sample must be finite. The estimators leave out the terms that a missing sample enters. A running sum cannot, so push! and append! refuse a sample that is not finite with an error.

Examples

julia> using SigmaTau

julia> x = [0.0, 1.0, 3.0, 2.0, 5.0, 4.0, 7.0, 9.0];

julia> acc = StreamingStability(:adev, 1.0, [1, 2]);

julia> append!(acc, x);

julia> snapshot(acc).dev ≈ adev(PhaseData(x, 1.0), [1, 2]; ci=false).dev
true
source
Base.push! — Method
push!(acc::StreamingStability, x) → acc

Add one phase sample x, in seconds, and update the running sum of every averaging factor: the sum of squared second differences for :adev (Dobrogowski and Kasznia (2007), Eq. (9)), the inner sum and the sum of its squares for :mdev (their Eqs. (11) to (14)), and the same with third differences for :hdev and :mhdev.

A sample that is not finite throws an ArgumentError and leaves the accumulator as it was.

source
Base.append! — Method
append!(acc::StreamingStability, xs) → acc

Add the phase samples xs, in seconds and in order. The result is that of push! on each in turn: the samples before one that is not finite are added, and the error is thrown at that one.

source

snapshot(acc::StreamingStability) → StabilityResult
snapshot(live::LiveStability) → Vector{StabilityResult}

Deviation over all the samples received so far, as a StabilityResult; for a LiveStability, one result per deviation.

dev is NaN at an averaging factor with fewer than two terms, and neff holds the number of terms. The result carries no noise type, EDF or confidence interval: for those, run the estimator on the record.

Live measurement

LiveStability holds one accumulator for each deviation and takes the readings as an instrument gives them: phase, fractional frequency, or the frequency of a counter in hertz. read_reading returns the next reading of a source, and NaN once its stream has ended:

using Sockets

counter = InstrumentSource(connect("192.168.1.20", 5025); query="READ?")
live = LiveStability([:adev, :mdev], 1.0, [1, 2, 4, 8, 16];
                     quantity=:hz, nominal=10e6)
while true
    reading = read_reading(counter)
    isnan(reading) && break
    push!(live, reading)
end
snapshot(live)            # one StabilityResult for each deviation

SimulatedSource stands in for the instrument while a setup is tried out. The command line follows a measurement with sigmatau live, and the explorer on its Live page.

SigmaTau.LiveStability — Type
LiveStability(devs, tau0, m_values; quantity=:phase, nominal=NaN)

Running deviations of a live measurement: one StreamingStability for each name in devs, all fed by push!(live, reading). snapshot returns one StabilityResult per deviation, equal to the estimator's on the readings so far, and nsamples the number of readings.

Arguments

  • devs: a vector of :adev, :mdev, :hdev and :mhdev.
  • tau0: interval between readings, in seconds.
  • m_values: averaging factors.

Keywords

  • quantity=:phase: what a reading is: :phase, a time error in seconds; :frequency, a fractional frequency, integrated to phase as FrequencyData is, so that n readings make n + 1 phase samples; or :hz, a frequency in hertz as a counter reads it, converted to fractional frequency against nominal.
  • nominal: the nominal frequency in hertz for :hz. By default it is the first reading rounded to four significant digits.

A reading that is not finite throws an error.

source
SigmaTau.SimulatedSource — Type
SimulatedSource(; white_pm=0, white_fm=1e-12, rw_fm=0, tau0=1.0, rng=nothing)

Simulated clock, for trying a live setup without an instrument. A reading is a phase sample in seconds, the sum of three independent Gaussian terms.

Keywords

  • white_pm=0: standard deviation of the white PM added to each phase sample, in seconds.
  • white_fm=1e-12: standard deviation of the white FM, as a fractional frequency per sample.
  • rw_fm=0: standard deviation of the step the frequency takes from one sample to the next, which makes random-walk FM.
  • tau0=1.0: sample interval in seconds.
  • rng: an AbstractRNG, for a reproducible stream.

At $τ_0$ the Allan deviation of the white PM term is √3·white_pm/tau0, that of the white FM term white_fm, and that of the random-walk FM term rw_fm/√2.

Examples

clock = SimulatedSource(white_fm=1e-12)
live = LiveStability([:adev], 1.0, [1, 10, 100])
for _ in 1:10_000
    push!(live, read_reading(clock))
end
snapshot(live)[1]
source
SigmaTau.InstrumentSource — Type
InstrumentSource(io; query="")

Readings from an instrument that sends lines of text. A reading is the first number on a line, as in a SCPI reply such as +1.000000000012E+07 or in comma-separated fields. Blank lines are skipped, and the stream ends with io.

With a query such as "READ?", the query is written before each line is read. Without one the instrument is expected to send readings on its own.

SCPI's not-a-number value, 9.91E+37, with which a counter reports a gate without a measurement, throws an error: the running sums cannot leave a sample out.

io is any open stream:

  • an instrument on the network, Sockets.connect(host, 5025): 5025 is the port registered for raw SCPI;
  • a serial port, opened as a file once its line speed is set: on Linux stty -F /dev/ttyUSB0 9600 raw, on macOS stty -f, then open("/dev/ttyUSB0", "r+");
  • a pipe, or a file of readings, read to its end.

Examples

using Sockets
counter = InstrumentSource(Sockets.connect("192.168.1.20", 5025); query="READ?")
live = LiveStability([:adev, :mdev], 1.0, [1, 2, 4, 8, 16];
                     quantity=:hz, nominal=10e6)
for _ in 1:3600
    push!(live, read_reading(counter))
end
snapshot(live)
source
