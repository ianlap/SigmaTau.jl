Data and files

Read records from text files and write records, results and suites back out. The readers accept whitespace-, comma- (.csv) and tab-separated (.tsv) columns, skip # comment lines and Stable32 headers, and take τ₀ from the time column, a # tau0: header or a Stable32 Tau: line. Reading and saving data walks through them.

Reading

SigmaTau.read_phase — Function
read_phase(path; tau0=nothing, time_col=1, value_col=2, header=0,
                 delim=nothing, scaling=1.0,
                 detrend=:none, fillgaps=false) → PhaseData

Read a phase-data file and return a PhaseData ready for stability analysis. The returned record carries path in its source field.

Leading # comment lines (the header that save writes) are skipped automatically; a # tau0: <value> entry supplies the sample interval when the tau0 keyword is omitted and a # start: <ISO 8601> entry the record's start_time, so files written by save(path, data) round-trip with no keywords at all; a # data interval 1.0 s note does the same. Stable32 exports (a text header closed by # Header End) are read the same way, with Tau: supplying the sample interval. # lines later in the file are skipped too. The file is read line by line, keeping only the time and value columns, so multi-day records at high rates load in the memory of their samples.

A time column of MJD values (from MJD 30000 to 90000, with steps under 0.05 d and more than four decimals) is read in days and sets the record's start_time; pass tau0 for seconds timestamps that look like that.

The time column places the samples on a grid: its step is the mean of the regular steps, rounded to the shortest value that keeps every timestamp within a quarter step of its slot, so jittered or coarsely rounded timestamps (MJD to six decimals) give the true τ₀. Each step is rounded to a whole number of grid steps, so a missing reading leaves a NaN sample where it belongs, which the gap-tolerant estimators skip (see Timestamps and gaps). A record with no missing timestamps is read exactly as written. A column that is not a time axis (not increasing) leaves the samples in file order, and a file with one column is read as its values (time_col=0, value_col=1).

Keyword arguments

  • tau0: sample interval in seconds. When omitted, taken from a # tau0: comment header if present, else from the time column (its grid step); required when time_col=0 and neither fallback applies.
  • time_col: 1-based column index for timestamps (0 = no time column; the samples are then taken in file order, as they are when time_col == value_col).
  • value_col: 1-based column index for phase samples.
  • header: number of non-comment header lines to skip (counted after any leading # comment lines).
  • delim: field delimiter (Char). Auto-detected from extension when nothing (, for .csv and tab for .tsv when the first data line holds one, whitespace otherwise).
  • scaling: multiply phase samples by this factor (e.g. 1e-12 for ps→s).
  • detrend: one of :none, :mean, :endpoint, :linear, :quadratic. See detrend.
  • fillgaps: when true, fill the missing samples (and any NaN reading) with fillgaps (Howe's algorithm). Requires a time column.

Examples

pd = read_phase("phase.csv")                          # 2-col CSV, auto tau0
pd = read_phase("p.tsv"; detrend=:linear)             # remove linear trend
pd = read_phase("p.txt"; time_col=0, tau0=1.0)        # no time column
pd = read_phase("g.csv"; fillgaps=true, scaling=1e-9) # ns→s + Howe fill

Timestamps and gaps

A time column places the samples. The grid step is the mean of the regular steps, rounded to the shortest value that keeps every timestamp within a quarter step of its slot, so timestamps rounded to a coarse resolution (MJD to six decimals is 0.0864 s) still give the true τ₀. Each step between timestamps is rounded to a whole number of grid steps, so jittered timestamps keep every reading in order and a reading missing from the log leaves a NaN sample in its slot instead of joining the samples around it end to end. adev, mdev, hdev, mhdev, tdev, htdev, mtie and tierms skip the terms that read a missing sample; the total deviations, Theo1 and the spectra return NaN until the gaps are filled with fillgaps (or fillgaps=true on the readers). A record with no missing timestamps is read exactly as written, and a column whose steps fit no grid (not increasing, or steps a quarter or more off a whole multiple) leaves the samples in file order. In a table, a row with no reading in the clock column is a missing reading too, so a column logged every 5 minutes in a 30-second table keeps its 5-minute step.

ISO 8601 timestamps (2026-11-08T21:41:03.5Z, with a ±hh:mm offset or none for UTC) and MJD time tags also give the record its UTC start time, which save writes as # start: and the readers read back.

The readers stream the file line by line and keep only the columns they return, so a multi-day log at a high rate costs the memory of its samples.

SigmaTau.start_time — Function
start_time(data::PhaseData) / start_time(data::FrequencyData) → DateTime or nothing

UTC time of the record's first sample (to the millisecond), or nothing when the record does not know it. The readers take it from ISO 8601 or MJD timestamps and from the # start: line save writes; sample i is at start_time(data) + (i − 1)·τ₀.

Instrument files

read_data reads the files instruments and their software write, detecting the layout: TimeLab .tim logs (which is how the Microchip 53100A, 5120A/5125A and TimePod are usually recorded), Stable32 .phd / .frd, Keysight 53230A-style counter readings, and logs with named columns such as GPSDO exports. sigmatau --input-format and the explorer's import dialog use the same readers.

SigmaTau.read_data — Function
read_data(path; format=:auto, tau0=nothing, column=nothing, nominal=nothing,
                kind=:auto, scaling=1.0, delim=nothing, fillgaps=false) → PhaseData or FrequencyData

Read a measurement file in any of the INPUT_FORMATS, detected with detect_format unless format names one. The record type follows the file: TimeLab logs and counter time-interval readings are phase, .frd files and counter frequency readings are frequency, and a named column is phase or frequency by its name.

  • tau0: sample interval in seconds; by default from the file header (TimeLab Sample Interval, Stable32 Tau:) or the grid step of the time column (seconds, MJD days, or ISO 8601 timestamps). A column named MJD is read in days, and so is one whose values lie between MJD 30000 and 90000 with steps under 0.05 d and more than four decimals, unless its name says seconds.
  • column: the clock column of a :table file, by 1-based index or by name. By default the only column besides the time column, else the one whose name says phase / time error / PPS, else frequency.
  • nominal: nominal frequency in Hz for readings in Hz (counter logs, a table column named … (Hz)); converted to fractional frequency (f − nominal)/nominal. By default the mean reading rounded to four significant figures.
  • kind: :phase or :frequency overrides the record type.
  • scaling: multiplies the samples after any unit conversion from a column name ((ns), [ps], ppb …).
  • delim: field delimiter of counter and table files; by default a comma or tab when the first data line holds one, else whitespace.
  • fillgaps: fill the missing samples (and any NaN reading) with fillgaps.

A time column (seconds, MJD days or ISO 8601 timestamps) places the samples as in read_phase: a missing reading leaves a NaN sample in its slot, which the gap-tolerant estimators skip, and a record with none is read as written. A table row with no reading in the clock column is a missing reading too, so a column sampled more sparsely than the table keeps its own step. ISO 8601 and MJD timestamps also set the record's start_time. Files are read line by line, keeping only the clock and time columns.

Counter readings of 9.91E+37 (SCPI's "no reading") become NaN.

p = read_data("trace.tim")                  # TimeLab, τ₀ from the header
y = read_data("53230A.csv"; tau0=1.0)       # counter in Hz → fractional frequency
p = read_data("gpsdo.csv"; column="PPS offset (ns)")

SigmaTau.detect_format — Function
detect_format(path; delim=nothing) → Symbol

Name the layout of a data file from its extension and first lines, one of INPUT_FORMATS:

  • :timelab: a TimeLab .tim measurement log (also what the Microchip 53100A, 5120A/5125A and TimePod write through TimeLab): typed header fields such as DBL 0x… "Sample Interval" 0.1, then a TIC n block of phase samples in seconds.
  • :stable32: a Stable32 .phd (phase) or .frd (frequency) file.
  • :counter: frequency-counter readings in SCPI real format (+1.00000000012345E+07, as the Keysight 53230A and 53220A log them), one per line, optionally after a timestamp (seconds or ISO 8601).
  • :table: numeric columns under a line of column names (a CSV export, most GPSDO and logging-script output).
  • :bipm_utc: a BIPM UTC - UTC(k) file from the time department's utclab directory (MJD [UTC-UTC(NIST)]/ns uA/ns …): one row every five days with the difference in nanoseconds, read as phase in seconds.
  • :rinex_clk: a RINEX 3 clock file (.clk, IGS and CODE clock products): AS satellite and AR station clock biases in seconds, many clocks on one epoch grid. column (1-based, in order of first appearance) or column_name (G08, ALGO00CAN) picks the clock, by default the first. Old files' D exponents (-.123D-03) are read too. Unzip .gz files first.
  • :columns: plain numeric columns, read by read_phase and read_frequency. read_data takes them as phase, unless the readings' median size is under 1e-11, which only fractional frequency has.

delim is the field delimiter, by default a comma or tab when the first data line holds one, else whitespace.

Checking a record

SigmaTau.summarize — Function
summarize(data::PhaseData) → NamedTuple
summarize(data::FrequencyData) → NamedTuple

A quick check of a record before analysis, as the explorer's Data page shows it:

  • n: number of samples;
  • tau0: sample interval in seconds;
  • span: n · tau0, the record length in seconds;
  • gaps: number of NaN samples;
  • outliers: indices from find_outliers at nsigma = 5;
  • drift_per_day: least-squares slope of the fractional frequency against time, per day (NaN with fewer than three finite frequency samples).

Examples

julia> using SigmaTau

julia> s = summarize(PhaseData(0.5e-9 .* (0:99) .^ 2, 1.0));

julia> (s.n, s.gaps, round(s.drift_per_day; sigdigits=3))
(100, 0, 8.64e-5)

Writing and loading

SigmaTau.save — Function
save(path::AbstractString, data::PhaseData)      → path
save(path::AbstractString, data::FrequencyData)  → path
save(path::AbstractString, r::StabilityResult)   → path
save(path::AbstractString, s::StabilitySuite; source_file="") → path

Write a SigmaTau object to a plain text file at path. Returns path so the call can be chained.

For PhaseData / FrequencyData the file is two delimited columns, sample time (i-1)·τ₀ in seconds and the sample value, preceded by a comment header recording the provenance (and, when the record knows it, the UTC time of its first sample as # start: 2026-11-08T21:41:03Z):

# SigmaTau phase data
# source: user
# tau0: 1.0
0.0     -1.7881e-10
1.0     2.1406e-10
…

source is "user" for records constructed directly from a vector and the originating file path for records that came from read_phase / read_frequency. The delimiter follows the extension convention of the readers: , for .csv, tab otherwise. read_phase / read_frequency skip the comment header automatically and pick up # tau0: when no tau0 keyword is given (and # start:), so read_phase(save(path, pd)) reproduces pd exactly, and any external tool can consume the file as a plain two-column table. Typical use: generate noise with noise_gen and hand it to software outside SigmaTau.

For a StabilityResult the file is self-describing text: comment lines give the format version, the deviation type, τ₀, the sample count, the confidence level and whether intervals were computed, then a header and one tab-separated row per τ (tau dev noise_type ci_lower ci_upper edf neff; the interval columns hold "" / NaN when there are none). A StabilitySuite file has a metadata header (package version, timestamp, the optional source_file, data kind, τ₀, N, confidence, τ grid, deviations) and one such table per result. load reads any of these files back.

Note

FileIO.jl also exports a save function. If both packages are loaded, qualify the call as SigmaTau.save(path, data).

Examples

pd = noise_gen(PhaseData, 4096, 1.0; sigma1=Dict(0 => 1e-12))
save("white_pm.txt", pd)
pd2 = read_phase("white_pm.txt")     # tau0 and values round-trip

r = adev(pd)
save("white_pm_adev.tsv", r)
load("white_pm_adev.tsv").dev == r.dev   # true

See also load, read_phase, read_frequency.

SigmaTau.load — Function
load(path::AbstractString) → StabilityResult | StabilitySuite | PhaseData | FrequencyData

Read a file written by save. The first line says what it holds: a suite file gives a StabilitySuite, a result file a StabilityResult, and a SigmaTau phase or frequency file a PhaseData / FrequencyData (through read_phase / read_frequency). For other data files call the readers directly.

Result files from v0.4 load with tau0 = NaN, n = 0, confidence = NaN and neff filled with zeros.

Note

FileIO.jl also exports load; qualify the call as SigmaTau.load(path) if both packages are loaded.
