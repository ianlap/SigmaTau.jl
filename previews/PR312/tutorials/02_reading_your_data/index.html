Reading and saving data

A record usually arrives as a text file: columns of numbers, a table that a logger wrote, or the export of an instrument or of another program. This tutorial writes three small files, reads each one back as a record, looks at what the reader made of it, and saves a record and its results. Data and files is the reference for every reader and format.

using SigmaTau
using Dates
using Random

dir = mktempdir()            # the files of this page go here
clock = noise_gen(PhaseData, 2048, 1.0; sigma1 = Dict(0 => 1e-11), rng = Xoshiro(1))

Columns of numbers

The plainest file has a time column and a column of samples, separated by blanks, by commas, or by tabs in a .tsv file. This one holds the time and the phase of the simulated clock, both in seconds:

file = joinpath(dir, "clock.txt")
open(file, "w") do io
    for (k, x) in enumerate(clock.x)
        println(io, k - 1, "  ", x)
    end
end
foreach(println, readlines(file)[1:3])
0  3.1957417504201744e-13
1  2.7938476633336265e-12
2  -3.4336690603624677e-12

read_phase needs no keywords for it. The sample interval is the step of the time column:

p = read_phase(file)
p.tau0, length(p)
(1.0, 2048)

The file is read line by line, so a long log costs the memory of its samples and no more. Keywords cover the other layouts: value_col and time_col choose the columns, header skips lines of text, scaling converts the unit of the samples, and a file with a single column takes its sample interval from tau0. read_frequency reads fractional frequency in the same way.

read_phase("log.txt"; value_col = 4, header = 1, scaling = 1e-9)  # nanoseconds
read_frequency("samples.txt"; tau0 = 0.1)                         # one column

Missing readings

A logger that drops readings leaves a file with rows missing. The readers place every sample by its time, so a missing row becomes a missing sample, NaN, and the samples on either side of it keep their distance. This file lacks twelve rows:

gapfile = joinpath(dir, "gaps.txt")
open(gapfile, "w") do io
    for (k, x) in enumerate(clock.x)
        k in 1001:1012 || println(io, k - 1, "  ", x)
    end
end

g = read_phase(gapfile)
length(g), count(isnan, g.x)
(2048, 12)

The Allan and Hadamard deviations, their modified and time forms, mtie and tierms leave the missing samples out, and a result counts the terms that were used:

adev(p, [8]).neff, adev(g, [8]).neff
([2032], [2004])

The total, Thêo, parabolic and dynamic estimators and the spectra need a complete record. Timestamps and gaps lists what every function does with missing samples, and Gaps, outliers and drift weighs filling them against analyzing around them.

A table from a logger

read_data reads files that carry more than numbers: a line of column names, units, timestamps, or the header of an instrument. This table holds the offset of a 1 PPS output in nanoseconds, beside a temperature:

pps = noise_gen(PhaseData, 600, 1.0; sigma1 = Dict(2 => 1e-9), rng = Xoshiro(2))
table = joinpath(dir, "gpsdo.csv")
open(table, "w") do io
    println(io, "timestamp,PPS offset (ns),temperature (C)")
    for (k, x) in enumerate(pps.x)
        t = DateTime(2026, 3, 1, 12) + Second(k - 1)
        println(io, t, "Z,", round(1e9 * x; digits = 3), ",31.5")
    end
end
foreach(println, readlines(table)[1:3])
timestamp,PPS offset (ns),temperature (C)
2026-03-01T12:00:00Z,-0.863,31.5
2026-03-01T12:00:01Z,-0.734,31.5

The reader finds the format, takes the time column and the clock column by their names, and converts the samples to seconds by the unit in the name. The timestamps give the sample interval and the UTC time of the first sample:

q = read_data(table)
detect_format(table), q.tau0, start_time(q), q.x[1:2]
(:table, 1.0, Dates.DateTime("2026-03-01T12:00:00"), [-8.63e-10, -7.34e-10])

The same call reads the .phd and .frd files of Stable32, the .tim files of TimeLab, the readings of a counter, the BIPM files of UTC − UTC(k) and RINEX clock files. The docstring of read_data states how each format is read, how a column is chosen when a table has several, and where a file can be read wrongly.

A first look

summarize reports what a record holds before any analysis: its length and span, the number of missing samples, the indices of its outliers and the slope of its fractional frequency, per day. pairs lists the fields one to a line:

pairs(summarize(g))
pairs(::NamedTuple) with 6 entries:
  :n             => 2048
  :tau0          => 1.0
  :span          => 2048.0
  :gaps          => 12
  :outliers      => Int64[]
  :drift_per_day => 1.50474e-11

Gaps, outliers and drift goes through the preparation of a record. read_phase and read_frequency can also remove a trend and fill the gaps as they read, with the keywords detrend and fillgaps.

Saving a record

save writes a record as text, under comment lines that hold the file it came from, its sample interval and its start time:

saved = save(joinpath(dir, "pps.txt"), q)
foreach(println, readlines(saved)[1:6])
# SigmaTau phase data
# source: /tmp/jl_Bt2JsM/gpsdo.csv
# tau0: 1.0
# start: 2026-03-01T12:00:00Z
0.0	-8.63e-10
1.0	-7.34e-10

The readers take the last two from those lines, so the file reads back as it was written, without keywords:

back = read_phase(saved)
back.x == q.x, start_time(back) == start_time(q)
(true, true)

Saving results

A StabilityResult is saved as a table with tab-separated columns, which a spreadsheet opens, under comment lines that describe it. The file begins with those lines and the names of the columns:

r = adev(q)
resultfile = save(joinpath(dir, "adev.tsv"), r)
foreach(println, readlines(resultfile)[1:7])
# SigmaTau StabilityResult v1
# deviation_type=adev
# tau0=1.0
# n=600
# confidence=0.683
# calc_ci=true
tau	dev	noise_type	ci_lower	ci_upper	edf	neff

load returns what save wrote, whether a record, a result or a StabilitySuite:

load(resultfile).dev == r.dev
true
suite = stability(q)
suitefile = save(joinpath(dir, "suite.tsv"), suite; source_file = "gpsdo.csv")
load(suitefile)[:mdev].dev == suite[:mdev].dev
true

The command line and the explorer read the same files (The record; Opening a file).
