Data and files

The readers make a record from a text file, and save and load store records, results and suites. Reading and saving data works through them on a file.

FileRead with
Columns of numbers, with or without a time columnread_phase, read_frequency
Stable32 and TimeLab files, counter readings, tables with named columns, BIPM files of UTC − UTC(k), RINEX clock filesread_data, which finds the format
A file that save wroteload

The command line and the explorer read the same files (The record; Opening a file).

Columns of numbers

SigmaTau.read_phase — Function
read_phase(path; tau0=nothing, time_col=1, value_col=2, header=0, delim=nothing,
           scaling=1.0, detrend=:none, fillgaps=false) → PhaseData

Read a text file of numeric columns as a PhaseData record. Each line holds one sample, in seconds, in column value_col, and its time in column time_col. A file with a single column is read as the samples alone. The record carries path as its source.

The file is read line by line and only the two columns are kept, so the memory used is that of the samples. read_data reads instrument files and tables with named columns.

Header

Lines that begin with # at the head of the file are skipped, and three of them are read:

  • # tau0: 10.0 gives the sample interval in seconds;
  • # start: 2026-11-08T21:41:03Z gives the UTC time of the first sample (start_time);
  • # data interval 1.0 s, or # sample interval: 1.0 s, gives the sample interval when no # tau0: line does.

save writes the first two, so a saved record is read back without keywords. A Stable32 export begins with lines of text closed by # Header End. They are skipped, and their Tau: line gives the sample interval. Blank lines and lines that begin with # are skipped throughout the file.

Time column

The sample interval is the keyword tau0, else that of the header, else the step of the time column. An error is thrown when the file gives none and the keyword is absent.

The time column also places the samples. Its steps are fitted to an even grid, and a reading that is missing from the file leaves a NaN sample in its place (see Timestamps and gaps). A file with no reading missing is read as written.

The grid step starts from the mean of the steps shorter than 1.5 times the shortest. It is rounded to the fewest significant figures, at most six, for which two conditions hold: the rounded step differs from the least-squares step of the timestamps by no more than the uncertainty of that step, which their scatter about the fit sets, nor by more than 1 %, and every timestamp lies within a quarter step of its place. When no rounding passes, the step is the span of the timestamps over the number of steps. Timestamps that jitter, or that are rounded to a coarse resolution, therefore give a round $τ_0$, and exact timestamps keep their own step whatever the length of the record.

A column that is no time axis leaves the samples in file order: one that does not increase from line to line, or whose steps are not whole multiples of one step to within a quarter of it. $τ_0$ is then the median step, which must be positive, unless the keyword or the header gives it.

A time column is read as MJD when its values lie between 30000 and 90000, its median step is under 0.05 d and it has digits past the fourth decimal. It is converted to seconds and gives the record its start_time. MJD values at longer steps are read as seconds, so that daily data need tau0=86400. Timestamps in seconds that meet the three conditions are taken for MJD: pass tau0 for them, and disregard the start time.

Keywords

  • tau0: sample interval in seconds.
  • time_col=1: column of the timestamps, counted from 1. With 0, or with time_col == value_col, the file is read without a time column.
  • value_col=2: column of the samples.
  • header=0: number of lines to skip after the leading # lines, such as a line of column names.
  • delim: character that separates the fields. By default a tab in a .tsv file whose first line of data holds one, else a comma when that line holds one, else runs of blanks. A field may be enclosed in double quotes.
  • scaling=1.0: factor applied to the samples, 1e-9 for a file in nanoseconds.
  • detrend=:none: trend to remove from the samples, one of the methods of detrend.
  • fillgaps=false: true fills the missing samples with fillgaps, with the reservations stated there: the readings that the time column shows to be absent, and those written as NaN.

Examples

julia> using SigmaTau

julia> path = joinpath(mktempdir(), "phase.txt");

julia> write(path, "0 1.0e-9\n10 1.2e-9\n20 1.1e-9\n40 1.5e-9\n");

julia> p = read_phase(path);

julia> p.tau0
10.0

julia> print(p.x)
[1.0e-9, 1.2e-9, 1.1e-9, NaN, 1.5e-9]
p = read_phase("phase.csv"; scaling=1e-9)         # samples in nanoseconds
p = read_phase("samples.txt"; tau0=0.1)           # one column, no timestamps
p = read_phase("log.txt"; value_col=4, header=1)  # column 4, below the names

Timestamps and gaps

A time column places the samples. The readers fit its steps to an even grid of step $τ_0$, and a reading that is missing from the file leaves a missing sample, NaN, in its place, so the samples on either side of it keep their distance in time. A file without a time column is taken as evenly sampled, in file order. read_phase states how the grid is found and when a column is not taken for a time axis.

ISO 8601 timestamps and MJD values also give the record the UTC time of its first sample, which save writes and the readers read back:

SigmaTau.start_time — Function
start_time(data) → Union{DateTime, Nothing}

UTC time of the first sample of a PhaseData or FrequencyData record, to the millisecond, or nothing when the record does not carry it. The readers take it from ISO 8601 or MJD timestamps and from the # start: line that save writes. Sample i is at start_time(data) + (i − 1)·τ₀.

source

What a function does with missing samples depends on what it computes:

FunctionsWith missing samples
adev, mdev, tdev, hdev, mhdev, htdev, tiermsLeave out every term that reads a missing sample
mtieTakes the peak-to-peak of the samples measured in each window
totdev, mtotdev, ttotdev, htotdev, mhtotdev, pdev, theo1, theoh, dadev, dhdev, cross_adev, groslambert, cross_psd_y, cross_psd_x, and adev and hdev with overlapping=falseThrow an error
StreamingStability, LiveStabilityThrow an error at the sample and stay as they were
psd_y, psd_x, ssb_phase_noiseReturn NaN at every frequency
detrend, drift_fit, find_outliers, summarizeWork on the samples measured
fillgapsReturns a record without missing samples
remove_outliersReplaces the outliers and leaves the missing samples missing

The estimators of the first row follow SP1065 §10.4: a term counts when every sample it reads was measured. For ADEV these are three phase samples and for HDEV four, and MDEV and MHDEV need every sample of the averages they difference. The noise type is identified on the record with each gap bridged by a straight line. neff is the number of terms summed, and the EDF is that of a complete record of the length that gives as many terms.

In a frequency record a missing sample loses the phase change across it, so a term counts only when no missing sample lies within its span, and one gap in the middle of the record removes most of the terms at long averaging times. Converting such a record with PhaseData throws an error.

Gaps weighs the three ways to handle a record with gaps: skip them, analyze a complete stretch, or fill them.

Instrument files

read_data reads the files that instruments and their programs write and returns phase or frequency as the file has it. detect_format names the format it finds.

SigmaTau.read_data — Function
read_data(path; format=:auto, tau0=nothing, column=nothing, nominal=nothing,
          kind=:auto, scaling=1.0, delim=nothing,
          fillgaps=false, keep_zeros=false) → PhaseData or FrequencyData

Read a measurement file in one of the INPUT_FORMATS and return its record, phase or frequency as the file has it. The format is found by detect_format unless format names it.

Formats

  • :columns: numeric columns, read as read_phase reads them by default. The record is phase, or frequency when the median size of the samples is under $10^{-11}$. Phase samples can be that small, as the residuals of a low-noise comparison are: pass kind=:phase for them.
  • :stable32: a Stable32 .phd (phase) or .frd (frequency) file. A Type: line in its header overrides the extension. $τ_0$ is that of the Tau: header line, else the step of the time tags. With two columns or more, the first holds the time tags and the last the samples. Time tags above 30000 at steps under one day are read as MJD.
  • :timelab: a TimeLab .tim file. Its TIC block holds the phase samples in seconds, which are multiplied by the Scale Factor of the header, and Sample Interval is $τ_0$. A file with another kind of block throws an error.
  • :counter: readings of a counter in the format +1.00000000012345E+07, one on each line, alone or after a timestamp in seconds or ISO 8601. Readings of median size under 1 are taken as time intervals in seconds and make a phase record. Larger ones are taken as frequencies in hertz and make the frequency record $(f - f_0)/f_0$ about nominal. A reading of 9.91E+37, the SCPI value for not a number, becomes NaN. Without timestamps tau0 must be given: it is the gate time.
  • :table: columns under a line of names, as in a CSV export, described below.
  • :bipm_utc: a UTC - UTC(k) file of the BIPM, with one row every five days that holds the MJD and the difference in nanoseconds. The record is phase in seconds.
  • :rinex_clk: a RINEX clock file. The record is the clock bias, in seconds, of one satellite (AS records) or station (AR records), chosen by column. Exponents written with D are read. A compressed file must be unpacked first.
Gaps in Stable32 files

Stable32 marks a missing sample with a value of zero (Stable32 manual, "Gaps & Outliers"). This reader does the same: a zero in a :stable32 file becomes NaN, except the first and the last sample of phase data. keep_zeros=true keeps every zero as a sample, as a record of quantized readings needs.

Named columns

In a :table file the time column is the first whose name is t, time, timestamp, date, datetime, utc, epoch, elapsed, sec, seconds or mjd, with or without a unit in brackets after it, else the first column that holds ISO 8601 timestamps. Numbers in it are read as seconds, or in the unit that its name gives when that is one of the units of time listed below, as in time (ms): minutes and hours are not among them. They are read as days when the name contains mjd, or when they meet the MJD conditions of read_phase and the name has neither sec, elapsed nor one of those units.

The clock column is column. By default it is the other column of a file with a time column and one more, else the only column whose name holds phase, time err, tie, pps, time offset, time diff or x, else the only one whose name holds freq, ffe, osc, fractional, ratio or y. An error lists the names when none of these decides.

A unit in the name of the clock column sets the type of the record and converts the samples. The units of time ps, ns, us, µs, ms and s make it phase, in seconds. The units ppt, ppb and ppm and the ratios of times from ps/s to s/s make it fractional frequency, and so does Hz, about nominal. Without a unit the words of the name decide: the record is frequency when the name holds one of the frequency words and none of the phase words, and phase otherwise.

A row without a number in the clock column is a missing reading. With a time column such rows are left out before the grid is fitted, so a column logged at a longer interval than the table keeps its own interval.

Timestamps

Where a file has timestamps, they place the samples as in read_phase: they give $τ_0$ when the keyword and the header do not, and a reading missing from the file leaves a NaN sample. ISO 8601 timestamps and MJD values give the record its start_time.

Keywords

  • format=:auto: one of INPUT_FORMATS, or :auto to detect it.
  • tau0: sample interval in seconds. By default that of the header of the file, else that of its timestamps. An error is thrown when the file has neither.
  • column: the clock to read. In a :table file, the number of its column, counted from 1, or its name. In a :rinex_clk file, its position in order of first appearance, or its name, such as "G08"; by default the first clock. Names are matched without regard to case.
  • nominal: nominal frequency in hertz, for readings in hertz. By default the mean reading rounded to four significant figures.
  • kind=:auto: :phase or :frequency sets the type of the record whatever the file suggests. Counter readings are then read as seconds under :phase and as hertz under :frequency, and a table column whose unit is of the other kind throws an error.
  • scaling=1.0: factor applied to the samples after any conversion of units.
  • delim: character that separates the fields of a :columns, :counter or :table file. By default a :columns file follows the rule of read_phase. In the other two a comma, else a tab, separates the fields when the first line holds one, and runs of blanks otherwise.
  • fillgaps=false: true fills the missing samples with fillgaps, with the reservations stated there: the readings that the timestamps show to be absent, and those that are NaN.
  • keep_zeros=false: true reads the zeros of a :stable32 file as samples and not as gaps.

SigmaTau.detect_format — Function
detect_format(path; delim=nothing) → Symbol

Name the format of a measurement file, one of INPUT_FORMATS, from its extension and its first 200 lines. The tests are made in the order of the table, and the first that holds decides.

FormatRecognized by
:timelaba TIC block after header fields such as DBL 0x… "Sample Interval" 0.1
:stable32the extension .phd or .frd
:bipm_utca heading MJD [UTC-UTC(k)]/ns in the first five lines
:rinex_clka RINEX VERSION / TYPE line of type C in the first five lines
:counterone or two fields on every line, the last a reading such as +1.00000000012345E+07 and the first, if any, a number or an ISO 8601 timestamp
:tablea line of column names above rows of numbers
:columnsanything else

A file with a # Header End line, which closes the header of a Stable32 export, is :columns unless one of the first four tests holds. The counter and table tests read the first eight lines of data, and split them at delim: by default at commas, or at tabs, when the first of the lines holds one, and at runs of blanks otherwise.

read_data says how each format is read.

A first look

SigmaTau.summarize — Function
summarize(data::PhaseData) → NamedTuple
summarize(data::FrequencyData) → NamedTuple

A quick look at a record before analysis, as the explorer's Data page shows it:

  • n: number of samples.
  • tau0: sample interval, in seconds.
  • span: n·tau0, in seconds.
  • gaps: number of NaN samples.
  • outliers: the indices find_outliers returns at nsigma = 5.
  • drift_per_day: least-squares slope of the fractional frequency against time, per day; NaN with fewer than three finite frequency samples.

Examples

julia> using SigmaTau

julia> s = summarize(PhaseData(0.5e-9 .* (0:99) .^ 2, 1.0));

julia> (s.n, s.gaps, round(s.drift_per_day; sigdigits=3))
(100, 0, 8.64e-5)

Saving and loading

SigmaTau.save — Function
save(path, data::PhaseData) → path
save(path, data::FrequencyData) → path
save(path, r::StabilityResult) → path
save(path, s::StabilitySuite; source_file="") → path

Write a record, a result or a suite to a text file and return path. load reads the file back.

Records

A PhaseData or FrequencyData record is written as two columns, the sample time $(i-1)τ_0$ in seconds and the sample, after a comment header:

# SigmaTau phase data
# source: user
# tau0: 1.0
0.0     -1.7881e-10
1.0     2.1406e-10
…

The columns are separated by a comma when path ends in .csv, and by a tab otherwise. source is "user" for a record made from a vector, and the path of the file for a record that was read. A record that knows the UTC time of its first sample writes it as well, as # start: 2026-11-08T21:41:03Z.

read_phase and read_frequency skip the header, take $τ_0$ and the start time from it, and return the record as it was saved. Any other program can read the file as a two-column table.

Results

A StabilityResult is written as a tab-separated table with one row for each $τ$ and the columns tau, dev, noise_type, ci_lower, ci_upper, edf and neff. Comment lines before it give the format version, the estimator, $τ_0$, the number of samples, the confidence level and whether the result has intervals. Without intervals, the interval and EDF columns hold NaN.

A StabilitySuite is written as one such table for each result, after a header with the package version, the time of writing, source_file, the kind of data, $τ_0$, the number of samples, the confidence level, the $τ$ grid and the estimators.

FileIO.jl

FileIO.jl exports save and load as well. With both packages loaded, write SigmaTau.save(path, data) and SigmaTau.load(path).

Examples

julia> using SigmaTau

julia> x = PhaseData([0.0, 1.5e-9, 1.0e-9, 2.5e-9], 10.0);

julia> y = read_phase(save(joinpath(mktempdir(), "x.txt"), x));

julia> y.x == x.x && y.tau0 == x.tau0
true

julia> r = adev(x, [1]; ci=false);

julia> load(save(joinpath(mktempdir(), "r.tsv"), r)).dev == r.dev
true

SigmaTau.load — Function
load(path) → StabilityResult, StabilitySuite, PhaseData or FrequencyData

Read a file written by save. Its first line says what the file holds: a result, a suite, or a phase or frequency record. Other data files are read with read_phase, read_frequency or read_data.

A result file written by version 0.4 carries no $τ_0$, number of samples, confidence level or neff. It loads with tau0 = NaN, n = 0, confidence = NaN and neff zero.
